# DeepSeek Harness 启动动画 — 实现规格与重构指南

本文档记录**行为规格**、**全部实测数据**、**架构决策**，以及**已经踩过的每一个坑**。

重构时请先读完第 5 节（坑清单）—— 那里每一条都对应一次真实的失败，其中至少三条是"看起来能跑但功能整块不生效"的类型。

---

## 1. 这是什么

一个 Windows 独立启动器（约 100 KB 的 WPF exe）。双击后：

1. 自己开一个窗口占住 DSH 会话窗口的位置
2. **同时在后台启动 DeepSeek Harness** —— DSH 自己的加载画面（"Loading plugins…" 和主题装饰）发生在动画窗口**背后**，看不见
3. 播一段 17.43 秒的开场动画，期间在空白段绘制三块信息面板
4. 爆闪收尾时淡出，露出已经加载好的 DSH 窗口

**核心洞察**：DSH 启动必然要花时间、必然显示它自己的加载界面。**不要试图消除它，把它盖住。** 它照常发生，只是发生在看不见的地方。

### 为什么是独立 exe 而不是 DSH 插件

因为 DSH 显示"Loading plugins…"的时候，正是在**加载插件**。任何插件代码都要等自己加载完才能运行 —— 那时官方加载画面已经显示过了。插件**在结构上无法**抢到它前面。

独立 exe 没有这个约束：它先占屏幕，DSH 在它背后启动。

## 2. 行为规格

### 2.1 时序

```
t=0.00   窗口出现（位置尺寸见 §3.1）
         同时启动 DSH（异步，不等待）
t=0.00   播 link-start.wav              1.170 秒
t=1.17   开始播 intro_dsh.mp4           17.430 秒
           └─ 7.58–8.85s    语言选择面板
           └─ 8.92–10.38s   登录面板
           └─ 10.38–12.22s  确认面板（含账号名）
           └─ 12.72–13.25s  标题渐入
           └─ 14.00s        视频自带标题接管
           └─ 15.10–17.43s  蓝色爆闪（完整形态）
t=16.73  开始淡出（片尾前 0.7 秒，与爆闪收尾重叠）
t=17.43  淡出结束（正好等于片尾），窗口完全透明后关闭
```

**关键点：全程没有静止画面。** 淡出与爆闪收尾重叠，所以读起来是"蓝光散去、露出 DSH"，而不是"蓝屏停一下再切"。

### 2.2 视觉规格

| 元素 | 规格 |
|---|---|
| 画布 | 1920 × 1080（设计分辨率） |
| 视频 | 1920×1080, 60 fps, h264 High, yuv420p, bt709 |
| 窗口 | 无边框、置顶、不显示在任务栏 |
| 关闭按钮 | 右上角 `✕`，44×34，半透明白字 + 深色底 + 细边框 |
| 跳过 | `Esc` 或点 `✕` |

### 2.3 账号名

确认面板（10.38–12.22s）中央显示当前 DSH 账号名。

**读取路径**（两条都已验证可用）：

1. 读 `%USERPROFILE%\.dsh\.credentials.yaml`（或 `%DSH_HOME%\.credentials.yaml`）
   - 找 `deepseek-account-platform/default:` 块
   - 取 `token:` 和 `issuer:` 两个标量
2. 请求 `{issuer}/auth-api/v0/users/current`

```
GET https://platform.deepseek.com/auth-api/v0/users/current
x-dsh-auth-token: <token>              ← 注意不是 Bearer
x-client-bundle-id:                    ← 刻意留空
x-client-platform: desktop-win
x-client-version: 0.2.0-rc.2
x-client-locale: ja_JP
x-client-timezone-offset: <秒数，取负>
```

响应 `{code:0, data:{biz_data:{id_profile:{name:"YukiRinne"}}}}` → 名字在 `data.biz_data.id_profile.name`。

**异步执行，绝不阻塞动画。** 取不到就显示占位文字，动画照常。

### 2.4 失败行为

**所有失败路径都通向"启动 DSH"**：视频缺失、语音缺失、账号读不到、播放异常 —— 都不能让用户卡在动画里。

硬上限 `MaxHoldSeconds`（默认 25 秒）保证窗口一定关闭。

## 3. 关键实现细节

### 3.1 窗口几何

**必须用 DSH 窗口的客户区（client rect），不是窗口矩形（window rect）。**

```
GetClientRect(dsh) + ClientToScreen(dsh, {0,0})   ← 正确：内容区
GetWindowRect(dsh)                                 ← 错误：含标题栏
```

用错会导致整个动画**错位一个标题栏的高度**（约 32px），淡出露出 DSH 时对不齐。

**DPI 换算**：`GetWindowRect` 返回物理像素，WPF 的 `Left/Top/Width/Height` 是 DIP。
缩放比 = `GetSystemMetrics(SM_CXSCREEN) / SystemParameters.PrimaryScreenWidth`。

### 3.2 窗口尺寸的三种取舍

**DSH 客户区不是 16:9，所以"不留黑边""不裁切""窗口贴合"三者只能满足两个。**

以 1280×820 客户区为例：

| 模式 | 窗口 | 画面 | 代价 |
|---|---|---|---|
| `aspect` | 1458×820 | 完整 | 比 DSH 宽 178px |
| `fill` | 1280×820 | 铺满 | 左右各裁 89px |
| `fit` | 1280×820 | 完整 | 上下各留 50px 黑边 |

`aspect` 的做法：取**至少覆盖**客户区的 16:9 框，居中。

```csharp
double w = r.Width, h = r.Height;
const double A = 1920.0 / 1080.0;
if (w / h < A) w = h * A;   // 太窄 → 加宽
else           h = w / A;   // 太矮 → 加高
```

**注意**：取"最大内接"而非"最小覆盖"会露出 DSH 的一条窄边。

### 3.3 帧号映射

```
f = 90 + 秒数 × 60          秒数 = (f − 90) / 60
```

**面板帧区间**（源视频时间轴）：

| 面板 | 帧 | 时间 |
|---|---|---|
| 语言选择 | 545 – 621 | 7.583 – 8.850 s |
| 登录 | 625 – 713 | 8.917 – 10.383 s |
| 确认 | 713 – 823 | 10.383 – 12.217 s |
| 标题渐入 | 853 – 885 | 12.717 – 13.250 s |
| 视频标题接管 | 930 | 14.000 s |

### 3.4 标题渐入曲线（照抄，不要自己拟）

来自原实现的 `BootTimeline.WelcomeOpacity`：

```csharp
Frames  = {852,853,855,858,860,863,865,868,870,873,875,878,881,883,885,942}
Opacity = {0,.035967,.074795,.115770,.165673,.244212,.325668,.400337,
           .485093,.572516,.664800,.752496,.846940,.922395,1,1}
```

**背景**：视频里烘死的标题在第 930 帧**一帧之内从无到满**（实测：13.983s 时 ink=0，14.000s 时 ink=137198）。所以要在它出现之前，用同一张图在同一位置做渐入 —— 12.717s 起淡入，13.250s 满，保持到 14.000s 交给视频。

因为两者是同一张图、同一位置，**交接完全无缝**。

顺带填掉了 12.22–14.00s 那段空白（原来的 1.78 秒全白）。

  阴影 = rect 下移 2px，颜色 #55808080，线宽 edge+3
  填充 = fill，描边 #929697，线宽 edge

| 语言次面板 | (854, 347) 605×110, r=30, `#0086EE`→`#00D3D9` |

### 3.6 蓝色爆闪

实测剖面（blueness = `mean(B - (R+G)/2)`）：

```
15.10   21.5   ← 开始
15.50   80.1
16.00  106.1   ← 峰值
16.40   95.6
16.70   70.0
17.00   31.0
17.40    1.0   ← 结束
```

**完整长度 2.3 秒，裁剪必须保留到 17.40s。**

> 教训：早期版本在 16.03s（峰值）就切断，只留了 0.93 秒 —— 整个"绽放后收拢"的后半段全丢了。当时是因为"硬切要求末帧全蓝"，但改成淡出后这个约束就不存在了，**裁剪点却没跟着改**。约束变了要回头检查依赖它的决定。

## 4. 架构

### 4.1 阶段流程

```
Main()
 ├─ --check   → 只读账号，写 logs\check.txt，退出（不开窗口）
 ├─ --bounds  → 只读 DSH 窗口矩形，写 logs\bounds.txt，退出
 ├─ 单实例互斥锁（Local\DeepSeekHarnessStartup）
 └─ Application.Run()   ← 不带窗口参数
      └─ Startup 事件 → Prepare()
           ├─ 启动 DSH
           ├─ LoadLayer()      载入标题图 / 启动账号读取 / 启动帧号定时器
           ├─ 固定矩形？ → 直接 ShowWindow()
           ├─ 有缓存？   → 直接 ShowWindow()
           └─ 否则轮询 DSH 窗口 → 找到后 ShowWindow()
                └─ Show() → Loaded → Reveal()
                     ├─ 播语音
                     └─ 语音结束（或 2.5s 超时）→ 播视频
                          └─ 帧号定时器驱动面板
                          └─ 片尾前 0.7s → StartFade()
                               └─ 淡出完成 → Close()
```

**`Application.Run()` 不传窗口参数** —— 窗口要等几何尺寸确定后才 `Show()`。传参数会立刻显示，产生全屏黑窗闪烁。

### 4.2 窗口几何的三种来源

| `WindowBounds` | 行为 |
|---|---|
| `"auto"`（默认） | 首次检测 DSH 窗口 → 写入 `geometry.json` → 之后直接读缓存，**立即出现** |
| `"fixed"` | 用配置里的四个值，**完全不检测** |

`auto` 是默认 —— 因为**发行给别人时不能写死**。`fixed` 是给固定环境追求零等待用的。

### 4.3 淡出重叠

淡出**从视频自己的播放位置触发**，不是另开计时器：

```csharp
if (!fadeRunning && film.NaturalDuration.HasTimeSpan
    && pos >= film.NaturalDuration.TimeSpan.TotalSeconds - FadeLeadSeconds)
    StartFade();
```

这样它天然跟随片子长度 —— 改裁剪点，淡出点自动跟着走。

## 5. 已踩过的坑

### 5.1 构建环境

| 坑 | 说明 |
|---|---|
| **编译器是 C# 5** | `csc.exe` v4.0.30319。**不支持 `?.`、`nameof`、`$"..."`、表达式体成员。** 用 `== null ? :` 代替 |
| `MediaFailed` 的事件参数 | 是 `ExceptionRoutedEventArgs`（`System.Windows` 命名空间），**不是** `ExceptionEventArgs` |
| 泛型委托签名必须精确 | lambda 推断失败时用 `delegate(Type a, Type b) {}` 显式声明 |
| 变量名遮蔽 | 方法参数 `e` 与 lambda 参数 `e` 冲突会报 CS0136，改名 |

### 5.2 控制流（**最严重的一类**）

| 坑 | 后果 |
|---|---|
| **提前返回让整块代码不可达** | `Prepare()` 在探测分支 `return`，而标题载入、账号读取、**帧号定时器**都写在它之后 → 默认配置下**永远不执行** → 三块面板和标题渐入全部不显示，看起来像"功能没做"，实际是死代码 |
| **方法名混用** | 一次重命名脚本失败（抛异常时还没写文件），导致定义叫 `Str` 而调用点叫 `Text`，编译失败 |
| **补丁脚本执行顺序** | 多个 patch 脚本有依赖关系时顺序颠倒 → 改动没落盘或锚点找不到。**每个脚本应自带断言，且写文件放在最后** |

> **重构建议**：把"必须执行"的初始化放在方法开头，绝不放在任何可能 `return` 的分支之后。或者干脆拆成独立方法，由调用方保证顺序。

### 5.3 窗口可见性

| 坑 | 说明 |
|---|---|
| **`Window.Opacity = 0` 不能隐藏窗口** | 没有 `AllowsTransparency` 的普通 WPF 窗口不能可靠地按部分不透明度合成 → 全屏黑窗照样出现。**用 `Visibility.Hidden` + 延迟 `Show()`** |
| **`Show()` 的时机** | 先按全屏尺寸 `Show()`、再缩到目标尺寸 → 用户看到"先全屏后缩小"。必须**先确定几何、再 Show** |
| **`Opacity` 动画需要窗口已创建** | 淡出用 `BeginAnimation(Window.OpacityProperty, ...)`，在 `Loaded` 之后才可靠 |
| **前台被抢** | 启动 DSH 会激活它已有的窗口并提到最前。需要 `Activate()` + 定期重申 `Topmost` |

### 5.4 网络

| 坑 | 说明 |
|---|---|
| **TLS 1.0 默认** | .NET Framework 4.x 默认只协商 TLS 1.0，Platform 拒绝 → `未能创建 SSL/TLS 安全通道`，请求根本没发出去。**必须显式打开 TLS 1.2**：`ServicePointManager.SecurityProtocol \|= (SecurityProtocolType)(3072\|768\|192)` |
| **`?.` 不可用** | 上面这条错误的诊断信息被 `?.` 挡过一次，只能看到空消息 |

> 这个 bug 靠读代码发现不了 —— 是加了 `--check` 诊断模式（不开窗口，只跑账号读取，结果写文件）才暴露的。**重构时保留这个模式。**

### 5.5 视频与裁剪

| 坑 | 说明 |
|---|---|
| **约束变了要回头检查依赖它的决定** | 裁剪点按"硬切要末帧全蓝"定的，改成淡出后该约束消失，但裁剪点没改 → 爆闪被砍掉 60% |
| **校验脚本自己会骗人** | 末帧检查的帧号列表硬编码到 962，于是它报的是"列表的末帧"不是"文件的末帧"，得出了错误结论。**用 `-sseof` 抽尾帧验证** |
| **视频流要逐帧拷贝** | `-c:v copy`，校验输出 `worst frame difference vs source: 0`。重编码会累积损失 |

### 5.6 并发

| 坑 | 说明 |
|---|---|
| **没有单实例保护** | 双击两次 → 两个动画窗口互相覆盖，看起来就像"动画不出现"。日志里同一进程时刻出现两次才暴露 |
| **日志会交错** | 多进程 `File.AppendAllText` 同一文件会插行。诊断时要意识到这一点 |

### 5.7 发行

| 坑 | 说明 |
|---|---|
| **写死本机路径** | DSH 路径写死在源码里 → 拿到发行包的人改不了（没有源码）。**必须放进配置文件** |
| **默认值不能是本机数据** | 一度把发行包默认设成 `WindowBounds: "fixed"` 加本机坐标 → 别人下载就是错的，正好犯了做自动检测要避免的错误 |
| **进程名从 exe 名推导** | 不要写死 `"DeepSeek Harness"`，用 `Path.GetFileNameWithoutExtension(DshPath)` |

## 6. 重构提示词

> 下面这段可以直接交给一个全新的 agent 使用。

---

请用 **C# / WPF** 实现一个 Windows 启动器，`.NET Framework 4.x`，用 Windows 自带的 `csc.exe`（`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）编译，**目标 winexe / x64**。不需要 SDK、NuGet 或工程文件。

**功能**：双击后在 DSH 会话窗口的位置开一个无边框置顶窗口，在后台启动 DeepSeek Harness，播一段 17.43 秒的开场动画，然后淡出露出已经加载好的 DSH。

**必须遵守：**

1. **编译器是 C# 5** —— 不能用 `?.`、`nameof`、字符串插值、表达式体成员。
2. **窗口几何取自 DSH 的客户区**（`GetClientRect` + `ClientToScreen`），不是窗口矩形。DPI 换算用 `GetSystemMetrics(SM_CXSCREEN) / SystemParameters.PrimaryScreenWidth`。
3. **窗口不要提前显示**。`Application.Run()` 不传窗口参数，几何确定后才 `Show()`。不要用 `Opacity = 0` 隐藏窗口（普通 WPF 窗口不支持）—— 用 `Visibility.Hidden`。
4. **所有初始化必须在任何 `return` 之前执行**。不要写成"分支里 return，后面还有代码"。
5. **单实例保护**：`Mutex(true, @"Local\DeepSeekHarnessStartup")`。
6. **TLS 1.2 必须显式打开**，否则请求 Platform 会失败。
7. **淡出从视频播放位置触发**（`pos >= duration - lead`），与片尾重叠，不要用独立计时器。
8. **失败路径全部通向"启动 DSH"**，并有 25 秒硬上限。
9. **日志**：记录 `begin` / `geometry` / `show` / `window` / `reveal` / `intro` / `film-ended` / `fade-out` / `fade-done` 及所有失败原因。另加 `--check`（只验账号）和 `--bounds`（只读窗口矩形）两个不开窗口的诊断模式。
10. **配置全部放 `launcher.json`，运行时读取**，包括 `DshPath`。默认值不能包含开发者本机的路径或坐标。

**动画绘制规格**见文档 §3.4–3.6：帧号映射 `f = 90 + 秒数 × 60`；面板帧区间 545–621 / 625–713 / 713–823；标题渐入曲线照抄 §3.4 的 16 个采样点；面板绘制参数照抄 §3.5 的表格。**面板缩放必须与视频用同一条规则。**

**账号**：读 `%USERPROFILE%\.dsh\.credentials.yaml` 里 `deepseek-account-platform/default` 块的 `token` 和 `issuer`，然后 `GET {issuer}/auth-api/v0/users/current`，请求头 `x-dsh-auth-token`（不是 Bearer）加五个 `x-client-*`。名字在 `data.biz_data.id_profile.name`。**异步执行，不阻塞动画。**

**先写设计再写代码**，不要把功能分散在可能提前返回的分支之后。
